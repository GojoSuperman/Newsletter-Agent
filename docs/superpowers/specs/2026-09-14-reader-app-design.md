# 뉴스레터 리더 앱 설계

> 기존 대시보드(`web/`)는 그대로 두고, **로컬 전용 뉴스 리더 웹앱**을 `app/`에 새로 만든다.
> 결정된 것: 같은 저장소 새 폴더 · FastAPI + 순수 JS SPA · 발행본 + 수집 전체 보기 · Actions 자동 실행 끄기 · 키는 로컬 설정 파일 · Discord는 선택 발송 · 뉴스 리더 UI · 단계 진행 표시.

---

## 1. 한 줄 정의

**"버튼 하나로 오늘 치 AI 뉴스레터를 만들고, 잡지처럼 읽고, 마음에 들면 Discord로 보내는 내 컴퓨터 안의 앱."**

기존 대시보드가 *운영 콘솔*(지표·로그)이라면, 이 앱은 *독자 화면*이다. 파이프라인(`newsletter/`)은 그대로 재사용하고 화면만 새로 짠다.

## 2. 화면

### 2-1. 전체 구조 — 3열 리더

```
┌──────────────────────────────────────────────────────────────────────────┐
│  ◎ AI 뉴스레터            [ ▶ 오늘 치 만들기 ]        [ 설정 ⚙ ]        │
├───────────────┬──────────────────────────────────────────────────────────┤
│  발행 목록     │  2026년 9월 14일 (일)              발행 2건 · 수집 23건  │
│               │  ────────────────────────────────────────────────────    │
│ ▸ 9월 14일 ●  │   [발행본 2]  [검수 탈락 2]  [수집 전체 23]              │
│   9월 13일    │                                                          │
│   9월 12일    │   ┌────────────────────────────────────────────────┐    │
│   9월 11일    │   │ AI타임스 · 09:12                                │    │
│   …           │   │ 아모데이 "AI 속도 조절 최대 난제는 중국과의 경쟁" │    │
│               │   │ 다리오 아모데이 앤트로픽 CEO는 … 세 문장 요약 …  │    │
│               │   │ ➜ 왜 중요한가 · AI 개발의 글로벌 경쟁 구도가 …   │    │
│               │   │                                  원문 보기 ↗    │    │
│               │   └────────────────────────────────────────────────┘    │
│               │   ┌────────────────────────────────────────────────┐    │
│               │   │ TechCrunch · 08:40                              │    │
│               │   │ …                                               │    │
│               │   └────────────────────────────────────────────────┘    │
│               │                                                          │
│               │   [ Discord로 보내기 ]   보낸 적 없음                    │
└───────────────┴──────────────────────────────────────────────────────────┘
```

- **왼쪽**: 만든 날짜 목록(호). 로컬에서 만든 것과 GitHub가 예전에 만든 것을 모두 보여주되 작은 표시로 구분. 오늘 것에 ● 표시.
- **가운데**: 그 호의 본문. 탭 3개.
  - **발행본**: 검수 통과 기사. 카드 = 출처·시각 / 헤드라인 / 3문장 요약 / "왜 중요한가" / 원문 링크.
  - **검수 탈락**: 요약은 됐지만 원문 대조에서 떨어진 기사. 탈락 사유를 빨간 줄로 표시. "이런 게 걸러졌다"를 보는 용도.
  - **수집 전체**: 그날 모은 기사 전부를 표로. 출처·시각·제목(링크). 선별된 5건에는 배지. 검색창 하나.
- **하단**: `[Discord로 보내기]` 버튼과 발송 상태(보낸 적 없음 / 9월 14일 07:41 발송). 웹훅 미설정이면 버튼이 비활성 + "설정에서 웹훅을 등록하세요".

### 2-2. 만들기(실행) 화면 — 상단 버튼을 누르면 본문 자리에 오버레이

```
┌──────────────────────────────────────────────┐
│   오늘 치 뉴스레터 만드는 중                  │
│                                              │
│   ✔ 수집        23건 · 소스 8/8              │
│   ✔ 선별        23 → 5건                     │
│   ◉ 취재        3 / 5                        │  ← 진행 중은 회전 표시
│   ○ 검수                                     │
│   ○ 정리                                     │
│                                              │
│   ▸ 상세 로그 보기 (접힘)                     │
│                       [ 취소 불가 · 약 1분 ]  │
└──────────────────────────────────────────────┘
```

끝나면 오버레이가 닫히고 왼쪽 목록에 새 호가 생기며 자동 선택된다. 실패하면 오버레이에 빨간 오류와 "상세 로그"가 펼쳐진다. 시간 창(기본 24시간)은 버튼 옆 작은 선택(24 / 48 / 72).

### 2-3. 설정 화면 — 우측에서 열리는 패널

```
┌─ 설정 ──────────────────────────────── ✕ ─┐
│                                            │
│  OpenAI API 키        [ sk-…7Qx  등록됨 ]  │
│                       [ 새 키 입력 ______ ] │
│  모델                 [ gpt-4o-mini   ▾ ]  │
│                                            │
│  Discord 웹훅 URL     [ 미등록 ]            │
│                       [ URL 입력 ________ ] │
│                                            │
│  기본 수집 시간 창     [ 24 ] 시간          │
│                                            │
│  저장 위치: store/local/settings.json       │
│  (이 컴퓨터에만 저장, Git에 올라가지 않음)   │
│                                            │
│                                [ 저장 ]    │
└────────────────────────────────────────────┘
```

- 키는 **입력 후 다시 보여주지 않는다**. 마지막 4자만 "등록됨 · …7Qx"로 표시.
- 저장 시 OpenAI 키는 모델 목록 호출 한 번으로 유효성을 확인하고, 웹훅 URL은 형식(`https://discord.com/api/webhooks/…`)만 검사한다.
- 시작 시 키가 없으면 첫 화면이 설정 패널을 자동으로 연다.

### 2-4. 시각 방향

- 잡지형 리더. 밝은 배경, 본문 서체 크게(17px), 카드 간격 넉넉하게. 강조색 하나(진한 남색).
- 기존 대시보드의 표·막대 같은 운영 요소는 넣지 않는다. 숫자는 헤더 한 줄("발행 2건 · 수집 23건")에만.
- 폭 900px 이하에서는 왼쪽 목록이 상단 가로 스크롤 칩으로 바뀐다.
- 프레임워크 없음. `index.html` + `app.js`(해시 라우팅 없이 상태 기반 렌더) + `style.css`.

## 3. 서버 (`app/server.py`, FastAPI, 포트 8100)

| 경로 | 역할 |
|---|---|
| `GET /` | SPA |
| `GET /api/settings` | 마스킹된 설정 `{openai_key_tail, openai_model, webhook_registered, hours}` |
| `PUT /api/settings` | 설정 저장. 보낸 키만 갱신, `""`는 삭제. 저장 전 검증(OpenAI 모델 목록 호출, 웹훅 형식) |
| `GET /api/issues` | 호 목록 `[{run_id, date, origin, published, collected, sent_at}]` — `store/runs/`(GitHub)와 `store/local/runs/` 둘 다 |
| `GET /api/issues/{run_id}` | 그 호의 State 전체 (수집·선별·초안·검수·로그) |
| `POST /api/run {hours}` | 실행 예약. 키 미설정이면 400. 항상 `dry_run=True`(발송은 별도) |
| `GET /api/run/{id}/events` | SSE. 기존 대시보드와 같은 계약(`{node, update}` … `__end__`) |
| `POST /api/issues/{run_id}/send` | 그 호의 검수 통과분을 Discord로 발송. 성공 시 State에 `sent_at` 기록. 이미 보냈으면 409 |

- 설정은 `store/local/settings.json`(gitignore). 실행 직전에 `os.environ`에 넣고 `llm.get_client.cache_clear()`로 키 변경을 반영한다.
- 실행 로직은 기존 `web/app.py`의 SSE 생성기와 같다. 중복을 피하기 위해 그 부분을 `newsletter/runner.py`로 뽑아 두 서버가 공유한다(기존 대시보드 동작은 안 바뀜).
- Discord 발송은 `newsletter/nodes/publish.py`의 `render_discord`를 그대로 쓰고, 발송 함수 `send_discord(drafts, webhook_url)`를 같은 파일에 추가한다.

## 4. GitHub Actions

`daily.yml`에서 `schedule:` 트리거를 제거한다. `workflow_dispatch`(수동 실행)는 남겨 두어 원하면 Actions 탭에서 돌릴 수 있다. 기존 대시보드의 "GitHub에서 가져오기"도 그대로 동작한다.

## 5. 폴더

```
app/
├─ server.py          # FastAPI (위 API)
├─ settings.py        # settings.json 읽기/쓰기/마스킹/검증
└─ static/
   ├─ index.html
   ├─ app.js          # 상태 → 렌더. 리더 / 실행 오버레이 / 설정 패널
   └─ style.css
newsletter/
├─ runner.py          # (신규) SSE용 실행 생성기 — web/app.py와 app/server.py가 공유
└─ nodes/publish.py   # (수정) send_discord() 추가
tests/
├─ test_app_settings.py
├─ test_app_api.py
└─ test_runner.py
```

실행: `uv run uvicorn app.server:app --port 8100` → http://127.0.0.1:8100

## 6. 에러 처리

- 키 없음 → 실행 버튼 비활성 + 설정 패널 자동 열림. API는 400.
- 실행 중 예외 → 오버레이에 오류 표시, 상세 로그 펼침. 호는 생성되지 않음.
- Discord 발송 실패(웹훅 4xx/5xx) → 버튼 옆에 오류 문구, `sent_at` 기록 안 함. 재시도 가능.
- 검수 통과 0건인 호 → "보낼 기사가 없습니다"로 버튼 비활성.
- 설정 저장 시 OpenAI 키 검증 실패 → 저장하지 않고 "키가 유효하지 않습니다".

## 7. 테스트

- settings: 마스킹, 부분 갱신, 빈 문자열 삭제, 웹훅 형식 검증, OpenAI 검증은 가짜 클라이언트 주입
- api: issues 목록이 두 출처를 합침, 상세 조회, 키 없을 때 run 400, SSE 이벤트 순서(stub 노드), send가 `post`를 한 번 호출하고 `sent_at`을 기록, 두 번째 send는 409
- runner: web/app.py와 app/server.py가 같은 생성기를 쓰고 기존 test_api가 그대로 통과
- 전부 네트워크·OpenAI·Discord 없이

## 8. 하지 않는 것
